# GEO Final Prototype

GEO 产品原型持续迭代仓库。

## 固定正式地址

- 正式地址：`https://leouhan.github.io/geo-final-922/`
- `index.html` 仅代表**已确认发布的正式版本**。
- 任何测试中、讨论中、未验收版本都不得直接覆盖 `index.html`。

## 发布流程（重要）

后续所有页面更新必须遵循“两阶段发布”：

1. **测试阶段**
   - 每次页面修改后，先生成独立测试版本，例如：
     - `preview/v126.html`
     - `preview/v127.html`
   - 测试版本可以持续修改、覆盖或迭代。
   - 此阶段**不得更新正式地址对应的 `index.html`**。
   - ChatGPT 只提供测试地址供用户验收，并明确说明“正式环境未更新”。

2. **正式发布阶段**
   - 只有当用户明确说出类似：
     - “发布”
     - “发布到正式地址”
     - “上线”
     - “发布 vXXX”
     才允许更新正式版本。
   - 正式发布时需要：
     - 将已确认测试版本归档到 `versions/vXXX.html`
     - 用该版本更新根目录 `index.html`
     - 更新 `CHANGELOG.md`
     - 提交 Git commit
   - GitHub Pages 部署完成后，固定正式地址才展示新版本。

## 版本目录规则

- `preview/vXXX.html`：测试版本，未正式发布
- `versions/vXXX.html`：已确认并归档的正式历史版本
- `index.html`：当前线上正式版本
- `CHANGELOG.md`：版本变更及发布记录
- `README.md`：项目规则与发布流程

## 发布原则

- **默认所有修改都是测试版。**
- **未收到明确发布指令，不得更新 `index.html`。**
- 即使测试版已经完成、用户已经查看，也不能自行视为正式发布。
- 正式地址需要保持稳定，避免他人在验收期间看到未确认改动。
